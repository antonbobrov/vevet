# Swipe

A drag and swipe engine for the web. You get clean coordinates; you decide how they look on screen.

Swipe handles pointer tracking, direction, inertia, rubber-band bounds, snap targets, rotation and scale. It does **not** move the DOM for you — so it fits any layout, canvas, or animation stack.

## Why Swipe

- **One API for mouse and touch** — including multi-finger pan
- **Feels native** — release inertia, rubber-band stretch, optional snap-to-target
- **You keep control** — apply `movement` / `diff` however you want (`transform`, canvas, GSAP…)
- **Built for products** — image viewers, custom scroll, dials, sliders, cards

## Two coordinate spaces

Swipe gives you two related views of the same gesture:

| Use this           | Fields                                              | Best for                                   |
| ------------------ | --------------------------------------------------- | ------------------------------------------ |
| **Pointer space**  | `start`, `prev`, `current`, `diff`, `step`, `accum` | One-shot gestures, direction, velocity     |
| **Movement space** | `movement`, `prevMovement`, `scale`                 | Persistent drag, bounds, rubber-band, zoom |

`diff` resets every gesture. `movement` and `scale` keep accumulating until you change them — ideal for pan/zoom UIs.

With [`pointers`](props#props.pointers) greater than `1`, pointer-space coords follow the **center** between fingers.

## How a gesture works

1. Pointer down → Swipe waits until [`threshold`](props#props.threshold) (and optional [`minTime`](props#props.minTime)) is met.
2. Then [`start`](callbacks#start) fires, followed by [`move`](callbacks#move) on each sample.
3. On release → [`end`](callbacks#end), optional direction callbacks, then **inertia** if enabled and fast enough — otherwise **rubber settle** (nearest snap, or back inside bounds).

If the user never crosses the threshold, `start` / `end` do not fire (rubber settle may still run). Wrong [`axis`](props#props.axis) or [`willAbort`](props#props.willAbort) → [`abort`](callbacks#abort).

## Initialization

:::caution

- Swipe only computes coordinates — apply them yourself in callbacks.
- For pan / bounds / zoom, prefer **`movement`** and **`scale`**.
- Set `transform-origin: 0 0` (or `top left`) on the transformed element so translate and scale compose cleanly.
  :::

### Simple drag

```js
import { Swipe } from 'vevet';

const el = document.getElementById('card');

const swipe = new Swipe({
  container: el,
  grabCursor: true,
  onMove: ({ diff }) => {
    el.style.transform = `translate(${diff.x}px, ${diff.y}px)`;
  },
  onEnd: () => {
    el.style.transform = '';
  },
});
```

### Bounded drag with rubber-band and inertia

```js
import { Swipe } from 'vevet';

const wrapper = document.getElementById('wrapper');
const thumb = document.getElementById('thumb');

const swipe = new Swipe({
  container: wrapper,
  thumb,
  grabCursor: true,
  inertia: true,
  overscroll: 50,
  bounds: () => ({ x: [0, 300], y: [0, 300] }),
  onMove: ({ movement }) => {
    thumb.style.transform = `translate(${movement.x}px, ${movement.y}px)`;
  },
});

swipe.setMovement({ x: 150, y: 150 });
```

### Snap on release

```js
const swipe = new Swipe({
  container: wrapper,
  thumb,
  inertia: true,
  bounds: () => ({ x: [0, 100], y: [0, 100] }),
  snap: () => ({ x: [0, 100], y: [0, 100] }),
  onMove: ({ movement }) => {
    thumb.style.transform = `translate(${movement.x}px, ${movement.y}px)`;
  },
});
```

On release, inertia and rubber settle aim for the **nearest** target.

### Direction and cleanup

```js
swipe.on('toLeft', () => console.log('swiped left'));

swipe.destroy();
```
